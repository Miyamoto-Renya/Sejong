# Sejong

Sejong은 Rust와 Python/Triton으로 구현한 확률 합성 모델이다. Rust가 모델·역전파·공유 사건·원본 편입·저장을 관리하고, Triton 커널을 HIP으로 실행한다. 통합 저장 형식은 `sejong-native-composite-v6`다.

의미 파서는 동결 MiniLM과 역할별 학습 head를 사용한다. 인원이 N명이면 scene은 `N²+1`, instruction은 `(N+1)²`, request는 `2(N+3)+1`개의 결과를 계산한다. 질문 파서는 anchor·goal을 선택하고 관계와 STOP을 조건부로 출력한다. 탐색 깊이는 질문에 등장한 술어 횟수에서 계산한다. 어휘 파서는 가변 길이 UTF-8 byte 입력을 처리한다.

## 실행

```bash
source /home/renya/Sejong/scripts/env.sh
python scripts/fetch-minilm.py
python scripts/create-native-data.py --out data/native-v6
bash scripts/train-native.sh runs/native-v6 data/native-v6

target/release/sejong query --model runs/native-v6/model --request data/native-v6/story-two.json
target/release/sejong sample --model runs/native-v6/model --request data/native-v6/query.json --seed 91
target/release/sejong read-weights --model runs/native-v6/model --request data/native-v6/weights.json --compare
```

자료 생성기의 기본 recipe는 인원 6명·술어 5개·최대 3단계 감독 경로다. `--people`, `--predicates`, `--max-depth`, `--query-examples`로 감독 자료를 정한다. 프로그램 감독은 목표 `Program`을 JSON으로 저장하고, 경로 길이별로 관측 수를 배분해 지정한 수의 프로그램을 추출한다. 모델 차원·학습량·학습률·readout 온도도 생성기 인자로 지정한다. 실제 사용한 설정은 `recipe.json`에 저장한다.

`fetch-minilm.py`는 공식 모델의 고정 revision과 SHA256으로 파일을 취득한다. Rust `tokenizers`가 자산의 `tokenizer.json`을 실행하고 Rust·Triton이 BERT를 실행한다. 현재 MiniLM의 위치 embedding 용량은 512토큰이다. 같은 GPU context에서 동일 encoder의 동결 가중치를 공유한다.

## 자원과 학습 정책

Host 예산은 Linux `MemAvailable`과 cgroup 잔여량, GPU 예산은 HIP의 실제 가용량을 사용한다. `budgets.memory_bytes`, 학습 `batch.memory_bytes`와 `batch.max_examples`, `gpu.memory_mb`로 별도 예산을 지정한다. 배치는 텐서 shape와 allocator의 실제 할당 단위에서 계산한다.

Native 학습은 활성 손실 항의 정규화된 가중 평균을 사용한다. `loss.weights`와 `query_loss.weights`로 비중을 지정한다. Memory 배경은 선언된 관측에서 독립 재표집한다. 정규분포 배경은 `background` 정책에서 표준편차와 zero 확률을 명시한다.

Optimizer의 평균화 길이는 관측 수와 예정 업데이트에서 계산한다. `optimizer`에서 평균화할 관측 수·epsilon·weight decay·gradient clipping을 지정할 수 있다. 체크포인트에 실제 배치·optimizer 설정·moments·RNG·자료 fingerprint를 저장한다. `checkpoint_every=0`은 최종 체크포인트 저장을 뜻한다.

## 원본과 확률 실행

| 명령 | 동작 |
| --- | --- |
| `train-role --spec --out [--resume]` | 의미·조건부 프로그램·어휘의 로컬 감독과 paired 학습 |
| `train-memory --spec --out [--resume]` | query 본체·affine 입구 준비와 K/V 사실 학습 |
| `train-value --spec --out [--resume]` | byte 요청의 SEP hidden으로 값 분포 학습 |
| `connect --spec --out` | 등록한 의미·어휘·사실 원본을 통합 |
| `revise --model --stage --spec --out [--resume]` | 이름으로 선택한 원본의 K/V 개정과 새 snapshot |
| `prepare --model --out` | 현재 가중치의 full/direct 수치 경계 재계산 |

Assembly의 `extra`로 사실 원본을 등록하고 `goal_routes`로 두 목적의 경로를 지정한다. 기본 경로는 `[a]`, `[a,b]`다. 사건의 독립 관계는 scan, 공유 사건 재진입은 MDD로 계산한다. 반복 어휘 선택은 마지막 사용까지 공유한다. Joint와 pullback은 입력 equality partition을 사용해 같은 행의 draw를 공유한다.

Memory는 선언된 context마다 동일한 FP64 실행 경로의 full/direct 분포를 대조해 TV 반경을 저장한다. K/V 개정 후 반경을 다시 계산한다. 답에는 `read_error`, `numerical_error`, `remaining`, 확률 구간과 최빈 답 판정을 함께 기록한다. 용량이 부족한 부분 탐색은 미처리 확률 질량을 보존한다.

값은 원시 byte열이다. JSON에서는 UTF-8 문자열 또는 `{"hex":"ff00fe"}`로 표현한다. `generate --raw`는 선택한 값을 그대로 출력한다. 독립 byte Transformer의 크기와 학습 설정은 `configs/*.toml`에 둔다.

# Native 입력과 학습 규격

규격은 `crates/sejong-core/src/native.rs`에 정의한다. 편입 경로는 spec 파일의 디렉터리를 기준으로 해석한다. 학습 결과는 `<run>/model/`에 저장한다. Role의 최종 재개 상태는 `<run>/checkpoint/`, 주기별 role 상태와 memory·value의 재개 상태는 `<run>/checkpoints/`에 저장한다.

## 역할과 프로그램

`train-role --spec <JSON> --out <run> [--resume <checkpoint>]`를 사용한다. `role`은 scene·instruction·request·query·lexical이며 `model`에 폭·층·head·FFN·정규화 설정·seed를 지정한다. 의미 head는 `encoder`의 동결 MiniLM을 공유한다.

`examples`는 `text`, `people`, `predicates`, `label`, `program`으로 구성한다. 목록의 순서가 해당 관측의 좌표다. 인원 수 N에서 다음 레이블을 사용한다.

| 역할 | 레이블 |
| --- | --- |
| scene | `agent×N+patient`, NONE=`N²` |
| instruction | `focus×(N+1)+excluded`, N은 좌표 유지, NONE=`(N+1)²−1` |
| request | `goal×(N+3)+selector`; selector는 개체 0…N−1, agent=N, patient=N+1, focus=N+2; NONE=`2(N+3)` |
| query | `program`의 목표 구조, `null`은 NONE; `label`은 0 |
| lexical | `meanings` 목록의 인덱스 |

```json
{
  "text": "Where does the first person whom alice called work?",
  "people": ["alice", "bob", "carol", "david", "erin", "frank"],
  "predicates": ["called", "helped", "visited"],
  "label": 0,
  "program": {"goal": 0, "anchor": 0, "steps": [{"predicate": 0, "reverse": false, "last": false}]}
}
```

Goal 0은 장소, goal 1은 물품이다. `reverse`는 관계 방향, `last`는 마지막 일치 사건 선택이다. 조건부 decoder는 root와 각 관계 이후의 다음 step·STOP을 학습한다. 입력에서 발견한 술어 횟수가 프로그램의 최대 step 수다.

`pairs`의 각 항목은 `left`, `right`, `equivalent`다. 같은 의미의 관측은 좌표를 정렬한 Jensen–Shannon 손실, 다른 의미의 관측은 정답 log 확률의 logistic 대비 손실을 사용한다. `loss.weights`의 이름은 `supervised`, `consistency`, `contrast`다. 빈 설정은 활성 항의 동일 비중을 뜻한다.

## 학습 자원과 optimizer

공통 설정은 `steps`, `learning_rate`, `optimizer`, `batch`, `checkpoint_every`, `resume`다. Role의 `batch_size=0`은 자동 크기, 양수는 명시적인 관측 수 예산이다.

```json
{
  "batch": {"max_examples": 64, "memory_bytes": 1073741824},
  "optimizer": {"momentum_examples": 4096, "variance_examples": 65536, "epsilon": 0.0, "weight_decay": 0.0},
  "checkpoint_every": 0
}
```

이 값들은 사용자가 지정하는 정책의 예시다. 생략한 배치 크기는 관측 수·실제 가용 GPU 메모리·텐서별 할당량에서 계산한다. 평균화 구간 H는 지정한 관측 수를 배치 수로 나눈 올림이며 `β=(H−1)/(H+1)`로 변환한다. 기본 momentum 구간은 관측 전체 한 회분, variance 구간은 예정 업데이트 전체다. 기본 epsilon과 weight decay는 0이며 gradient clipping은 `clip_norm`을 지정하면 적용한다.

실제 배치·optimizer 설정·moments·RNG·학습 fingerprint를 체크포인트에 저장한다. `checkpoint_every=0`은 최종 저장, 양수는 해당 업데이트 간격의 추가 저장이다.

## Memory와 native 값

`train-memory`의 `config`에는 `id`, `dimension`, `tokens`, `layers`, `heads`, `hidden`, `ffn_width`, `norm_epsilon`, `readout_temperature`, `residual_scale`, `seed`를 지정한다.

- `requests`, `values`: 고유한 입력·출력 byte 값 목록.
- `contexts`: 요청마다 `tokens×dimension` 길이의 context. 첫 token이 연속 request다.
- `target_queries`: 요청마다 dimension 길이의 query 감독 좌표.
- `value_targets`: 값마다 dimension 길이의 목표 벡터.
- `labels`: 요청별 목표 값 인덱스.
- `query_steps`, `query_learning_rate`, `min_query_learning_rate`: query 준비와 cosine 일정.
- `fact_steps`, `learning_rate`: K/V 학습량과 학습률.
- `query_loss.weights`: `target`, `background`, `midpoint` 항의 정규화 비중.
- `background`: 기본 `{"kind":"empirical"}`은 선언된 배경에서 독립 재표집한다. Gaussian은 `standard_deviation`, `zero_probability`를 명시한다.

`[request,1]`의 관측 행렬은 dimension+1 열의 rank를 가져야 한다. 입구는 streaming Givens QR로 피팅한다. Readout은 온도 T에서 `H[:,y]=2×target[y]/T`, `b[y]=−||target[y]||²/T`다. 준비는 각 선언 context의 full/direct FP64 값 분포와 정규화의 반올림을 반경에 반영한다.

`train-value`는 `model`, `requests`, `prompts`, `values`, `labels`, `steps`, `learning_rate`와 공통 정책을 받는다. SEP hidden에서 값 head를 학습한다. 값은 UTF-8 문자열 또는 `{"hex":"ff00fe"}` 형태다.

## 원본 편입과 개정

Assembly는 `scene`, `instruction`, `request`, `query`, `lexica`, `a`, `b`, `catalog`와 추가 원본·경로·예산을 받는다.

```json
{
  "extra": {"archive": {"kind": "memory", "path": "archive/model"}},
  "goal_routes": [["a"], ["a", "b", "archive"]],
  "budgets": {"memory_bytes": 4294967296}
}
```

사실 원본의 kind는 `memory` 또는 `native`다. 각 경로의 첫 원본은 catalog 입력을, 다음 원본은 앞 원본의 출력 값을 받아야 한다. 목적별 확률 경로는 서로 다른 owner들로 구성한다. 연속 `read-weights` 경로는 owner를 반복 사용할 수 있다.

Host 예산 기본값은 Linux `MemAvailable`과 cgroup 잔여량의 작은 값이다. 사건 노드·살아 있는 어휘 분기·joint tensor는 자료구조의 byte 비용을 계산한다. 부족한 용량은 `Capacity` 오류로 나타내고, 부분 frontier는 미처리 질량을 유지한다.

`revise --stage <등록 이름>`은 해당 memory의 K/V를 로컬 복제본에서 학습한다. 개정 spec은 `labels`, `steps`, `learning_rate`와 공통 정책이다. 본체·입구·입출력 규격을 확인하고 현재 가중치의 반경으로 새 snapshot을 저장한다.

## 질의와 결과

일반 질의는 `question`, `people`을 받는다. 생략한 people은 catalog에서 질문에 등장한 이름으로 구성한다. 이야기 질의는 `story`와 `predicates`를 함께 준다. `modes`는 등록 원본 이름별 `full`·`direct` 선택이다. `full:true`는 전체 확률 분기 계산을 요청한다. `max_rows`, `max_components`로 처리할 frontier 양을 지정한다.

Joint는 `{"joint":["alice","alice","bob"],"goal":1}` 형식이다. 같은 요청의 반복은 같은 draw를 공유한다. Tensor의 차수는 joint 입력 수, shape는 최종 값 수에서 계산한다.

`read-weights`는 `inputs`, `route`, `modes`를 받는다. 첫 full 입력은 펼친 context, 첫 direct 입력은 request 좌표다. 다음 원본은 앞 출력의 단위 공 투영을 받는다. `--compare`는 같은 입력의 full 경로와 수치 차이를 계산한다.

답의 `values`, `probabilities`, `lower`, `upper`는 같은 순서이며 마지막 확률 항은 NONE이다. `read_error`는 준비된 직접 읽기의 TV 반경 누적, `numerical_error`는 실제 합성 연산량에서 계산한 반올림 여유, `remaining`은 미처리 질량이다. `tolerance`로 추가 판정 여유를 지정한다. `certified`, `prediction`, `reason`에 최빈 terminal 판정을 기록한다.

# Rust–Triton GPU 경계

Rust Engine은 HIP 장치·stream·메모리 풀·컴파일 서비스와 커널을 소유한다. Tensor는 allocation 참조, offset, shape과 FP16·FP32·FP64·I32 dtype을 가진다. 마지막 참조를 해제하면 allocation을 같은 stream의 풀로 반환한다.

## 컴파일과 실행

영속 Python 서비스에 연산 이름·인자 signature·constexpr·장치 architecture·wavefront를 JSON-lines로 전달한다. Triton은 HSACO와 symbol·thread 수·shared memory·scratch 크기를 반환한다. Rust는 HIP module API로 결과를 로드하고 장치 주소·형상·scalar를 전달해 실행한다.

캐시 키는 연산 모듈·컴파일 서비스·Triton 버전·컴파일 설정을 포함한다. 커널은 `python/sejong_kernels/ops/`의 `kernels.py`, `common.py`, `parser.py`에 배치한다.

## 메모리와 연산

GPU 예산은 HIP가 보고한 가용량과 `gpu.memory_mb` 설정으로 정한다. 기본값 0은 가용량을 사용한다. Engine은 tensor 할당량과 재사용 풀을 관리하며 학습기는 실제 작업 tensor·gradient·optimizer state의 비용으로 배치를 계산한다.

일반 행렬곱·embedding·gather·RMSNorm·LayerNorm·GELU·ReLU·SwiGLU·RoPE·attention·cross-entropy·Adam을 제공한다. 관계 attention은 거리의 방향·로그 크기와 같은 identity 여부의 학습 bias를 사용한다. Concat·slice·reshape·곱·affine bias와 관계 bias의 gradient도 역전파 그래프에서 누적한다.

동결 MiniLM encoder는 공식 설정의 post-LayerNorm BERT를 FP32로 실행한다. 파서는 입력 개체·술어 수에 따른 tensor를 만들고, 질문 접두사별 조건부 선택을 계산한다. Query와 어휘 relational encoder의 폭·층·head는 모델 설정을 따른다. 입력 길이는 해당 encoder의 위치 규격과 계산할 attention tensor의 메모리로 결정한다.

준비된 memory는 query 본체·입구·K/V·readout을 FP64로 실행한다. 준비와 추론이 같은 `forward_row`를 사용해 선언된 요청의 full/direct 법칙을 계산한다. 학습 gradient와 optimizer state는 FP32다. Byte Transformer checkpoint는 backward에서 블록 내부 활성값을 재계산한다.

## 호스트 계산과 저장

Rust FP64는 Givens QR 입구 피팅, 행 법칙의 보정, 의미·사건 확률 합성, equality partition tensor를 계산한다. QR은 관측을 행 단위로 받고 좌표 차원에 따른 행렬을 보관한다. 경험적 행 보정은 두 FP64 실행의 query 차이와 total variation을 방향 반올림으로 누적한다.

호스트 추론은 `MemAvailable`, cgroup 잔여량과 명시한 바이트 예산을 적용한다. 접두사·행 캐시·공유 사건 그래프·결합 tensor의 형상에서 작업 공간을 계산한다. `sejong-core::numeric`의 정밀도·연산량 기반 오차는 결과의 `numerical_error`에 들어간다. 선언된 full 행에 대한 direct 읽기 보정은 `read_error`로 전파한다.

Safetensors는 원본 dtype을 보존한다. Native snapshot은 원본 파일·입출력·encoder identity·경로·보정값과 서명을 함께 저장한다. 같은 HIP context와 같은 digest의 동결 encoder는 GPU 가중치를 공유한다.

`parser_system`은 인원·술어·경로·어휘 길이 확장과 파서 미분을 대조한다. 공식 ONNX 참조 출력은 `scripts/parser-reference.py`로 생성한다. `memory_contract`는 실제 사실 학습·선언 행 보정·개정·재개를 연결한다. `native_system`은 학습한 원본의 질의·정답·저장 흐름을 실행한다.
